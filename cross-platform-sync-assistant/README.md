# 一、核心功能
本方案的核心目标是：当业务需求同时涉及PC端、H5端、App端和微信小程序等开发时，开发者仅需完成一个项目（如PC端）的开发与联调，然后用 AI 调用 Skill 自动将改动同步到另一项目（如H5端），实现一次开发即可同步到多端的功能。

# 二、主要技术方案
本方案面向 AI 编程代理，开发者只需先完成一个端的业务开发与验证，例如 PC 端，系统即可自动采集该端变更，并生成目标端可实现的结构化上下文，辅助 AI 在 其他端完成等价业务功能。
1. 基于 Git 的需求差异采集
系统自动识别源项目当前开发分支与 master 分支之间的代码差异，采集新增、修改、删除文件及具体代码块，形成当前需求的完整变更集合。
2. 增量同步检查点机制
系统基于源仓库、目标仓库和分支生成唯一同步状态 key，记录上次成功同步的提交 hash。后续 bug 修复或需求变更时，仅采集上次成功同步之后的增量变更，避免重复分析和遗漏变更。
3. 准备态与成功态分离
生成差异包时仅记录“已准备 diff”的提交位置；只有目标端代码生成、校验和人工确认完成后，才推进“已成功同步”的检查点，防止中断或失败后造成后续增量同步漏掉代码。
4. 面向 AI 的结构化上下文生成
系统将源端变更整理为 AI 可直接消费的结构化数据，包括变更文件列表、文件状态、diff 统计、完整 patch、提交列表、同步范围和目标项目信息。AI 以已验证的源端代码变更为输入，而不是仅依赖自然语言需求描述，从而降低语义理解偏差。
5. 异构技术栈适配规则
系统向 AI 提供源端与目标端的差异规则，也支持自定义配置规则，例如 React 到 Vue 的组件转换、PC 路由到 H5 路由的映射、接口响应结构差异、目标端无需实现的页面清单等，使 AI 在生成目标端代码时保留业务逻辑一致性，同时符合目标端技术栈规范。
6. 目标项目分支自动准备
系统自动在目标项目中创建或切换与源项目同名的开发分支，并基于目标项目 master 或远程同名分支准备开发环境，保证跨端同步分支的一致性。

# 三、与常规 Vibe Coding 的区别
区别在于：**不是通过自然语言重新描述需求生成代码，而是以已验证的源端代码变更作为输入**，结合 Git 增量差异、同步检查点和项目差异规则，生成面向 AI 编程代理的跨端代码实现上下文。
同时，通过“成功检查点 + 结构化 diff + 异构项目适配规则”的组合机制，支持需求开发、联调、测试和 bug 修复全过程中的持续跨端同步。

# 四、技术效果
本方案可减少多端重复开发工作量，缩短迭代周期；降低因人工理解偏差造成的功能不一致；减少跨端适配 BUG；并在后续需求变更或 bug 修复时，实现一端修改、多端同步的持续维护能力。
